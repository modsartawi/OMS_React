What this prototype is asking you to rule

  1. The breakpoint — one, and where. Default 900 px of work area: the rail stays beside the results on every laptop, and only a tablet-landscape window stacks. 104 measured column set B at ~470 px and the rail's floor is 250 px, so beside is structurally possible from ~740 px — 900 leaves headroom rather than being the limit. The alternative 1140 keeps every beside-layout roomy, at the cost that a 1280 laptop with the nav open never sees the approved device. Switch q/w and read the 960 row.
  2. Which way it stacks. Default: the rail moves above the results, because 099 ruled "did the promotion fire?" the first read and the verdict must not sit under the evidence. This is also 083's precedent (the summary rail goes above the grid, never behind a toggle). a/s switches it.
  3. Nothing is ever behind a toggle. At every width: the run strip's chips, the items grid, the promotions rail (fires and near-misses), a W line's message. The only things that hide are the ones 103 already ruled hideable — the line expansion and manual conditions — and they hide identically at all widths.
  4. The cross-highlight when the rail is no longer beside the lines. Default: the card prints the lines it touched (lines 10 · 20) at all widths, and the hover highlight is the enhancement on top. Switch d/f to hover-only and the stacked device loses the answer entirely — 104 called this "the only thing on screen that says which lines a promotion touched", so the printed list is the honest degradation.
  5. The chip bar under pressure. Wrap, never scroll, never truncate — 100 forbids a truncated chip, and there are at most eight. The tail (money + run controls) travels as one unit, so the strip can only ever break into two rows: chips, then tail. Switch b to eight chips and read the 780 device.
  6. The tables. The results table never sheds and never scrolls — the breakpoint is derived from it, so its column never drops below what set B needs. The elements trace is the only table that can outgrow its column (it lives inside the results column at 66 %), and it sheds rather than scrolls: ctr first, then unit. Both are identifiers that repeat down the column; the numbers never go. Switch x for the scroll alternative and c to force the shed at any width.
  7. The floor: 780 px of work area ≈ a 1024 px window. Below it the app shell scrolls horizontally and no further arrangement exists. This is an internal back-office tool — record it so nobody builds a phone layout.
