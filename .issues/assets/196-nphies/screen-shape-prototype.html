The refusal is attached to the row that caused it, not left as a sentence in a message box. This is the whole reason Failed is a form state and not only a list state.

Acts follow the row's Request state — and the corrected mapping is Pending ⇒ Retry, not Failed ⇒ Retry. RetryAuth (AuthService.cs:1155) re-POSTs the stored request JSON verbatim and re-processes the answer: it means "ask again, take the newer answer". A Failed row was never accepted, so its remedy is a corrected request, and a Rejected verdict is the payer's final word — a new authorization, not a retry.
