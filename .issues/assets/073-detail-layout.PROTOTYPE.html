2 · The pill rail — six promoted statuses

Owner ruling, this session: the Status tab is removed — the statuses are on top now. So the rail must not lose the record: a quiet All statuses (13) disclosure at the end of the rail opens the full breakdown statusBreakdownRows renders today, including the three code-only statuses. The tab is gone; the record is not.

PillSourceWhy promoted
ReadyreadyStatusDescriptionHas the order been prepared. First question on the floor.
AvailabilityavailabilityStatusDescriptionIs the stock actually there — the single most common cause of the unhappy path this screen exists for.
ApprovalapprovalStatusDescriptionInsurance / e-Rx clearance. Gates dispensing.
PaymentpaymentStatusDescriptionPaid vs due — decides whether cancelling needs a refund (isRefundRequired).
DeliverydeliveryStatusDescriptionWhere it is in the field.
CancellationcloseStatusDescriptionRelabelled. "Close Status" reads as completion; 072 established close ≡ cancel. Field name and codes unchanged — copy only, in document.json.
Disqualified, and why. consignmentStatus, controlStatus and notificationStatus carry no *Description companion — a rail of raw codes is a rail nobody reads, and the 406 precedent (deleted client-side code maps that never fired on live data) says do not invent one. They keep their rows in the disclosure, as raw codes, exactly as statusBreakdownRows shows them today. lastAction, clearStatus and acceptanceStatus are described but not lifecycle — last action is history (the Log tab is its real home), clear and acceptance are accounting/consent sub-states. Six is the rail's budget; these three lose the contest, not the record.
Severity mapping stays fog — deliberately. 072 fixed the palette at five (ok · go · warn · bad · mute) and 070 gave all five full token tiers, so the rail is a lookup. What is not known is the coded value set behind each of the six statuses — SIS.Api was unreachable this session, so any value→severity table written here would be invention. The build needs one live document plus the server's code list. Until then: unknown code ⇒ mute, blank ⇒ mute with an em dash. This is the map's "Status → severity rules" fog patch, now narrowed from thirteen statuses to six.

The row rule, stated once. Inside a card that renders: money and boolean rows always render (0.00 and "No" are answers); text rows are omitted when blank (no em-dash graveyard). This replaces today's FieldGroup behaviour, which em-dashes everything.
The fifth card exists. The reference's annotations mention a Driver card it never draws; we have courierDriver* + tracking*, and on a Dawaa Now delivery it is the most-wanted block on the screen. One field is deliberately never rendered: courierDriverMasterPinCode — a delivery PIN does not belong on a back-office screen.

4 · The unnamed accent, now named

070 ruled POS --fam-insurance #0B7C8C survives as the prescription accent but deliberately left 073 to name it. It cannot be called --accent (070 already spent that name on a hover ground) and it is not a command family (072 ruled it out of the bar). It is named for what it marks:

TokenValueSourceUsed by
--prescription#0B7C8CPOS --fam-insurance e-Rx card accent bar · "View prescription" link
--prescription-050#E3F0F2derived Ground of the Rx item tag
--prescription-800#085C68derived Ink on the -050 ground (the teal itself is too light on a tint)
Same -050/-800 tiering as 070's four severity families, so 071's dark-twin rule (roles, not lightness levels — they swap sides) applies to it unchanged. It is a marker, never a control: no button, no pill, no focus ring is ever this teal.

6 · The note field — retired from the surface

Ruling: the standing note textarea is removed. Add Note… opens a small dialog (textarea + Save); every other note-posting command carries an optional note field inside its own confirm dialog — which is exactly what RequestCloseDialog already does for the cancellation reason.

This is not only prototype fidelity. Today the note is coupled to the commands invisibly, and that coupling has already cost a workaround: DocumentDetailsPage keeps a pendingNote state solely because Change Store must post the note as it read when the picker opened, not as it reads when the operator finishes picking. Capturing the note at the moment of commit deletes that state and the ambiguity under it. The endpoints, actionType codes and request bodies are untouched — only where the text is typed moves, so this stays inside map 068's scope.

The displayed last note (note) keeps its home: the Fulfilment card's last row.

ChromePlacement
BackChevron at the start of the identity band. It is navigation, and it stays put whether or not any command is available. Today's separate toolbar row above the title disappears entirely.
RefreshEnd of the pill rail, as a quiet outlined button, with its spinner in place. Refresh's most visible effect is the pill rail — putting it anywhere else makes the operator look in two places. (Success stays silent; only failure toasts. Unchanged.)

The summary is the context you read the grid with; hiding it behind a toggle on the narrow viewport that most needs orientation is backwards.
