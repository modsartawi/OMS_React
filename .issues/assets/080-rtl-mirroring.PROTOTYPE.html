RTL mirroring of the reworked layout

Ticket 080 of map 068. The 073 device is authored once in a <template> and stamped three times — only dir and a .repaired class differ between stamps. Any difference between A and B that is not a deliberate mirror is a fault; the eight found are indexed in §2 and each is repaired in C.

Stacked, not literally side by side. Two devices in a 1280 px column are ~620 px each, which trips 073's max-width:900px breakpoint and collapses the rail — hiding the very two-column faults this ticket exists to find. Full-width stamps keep the desktop layout under test.

Copy stays Latin — the map rules Arabic translation content out of scope. Latin text in an RTL frame exposes every layout fault, and it keeps the visual diff against 073 readable.

2 · The eight faults

F1 Customer block uses margin-left:auto

It bites the moment the band wraps — a lone wrapped flex item with margin-left:auto is pushed to the physical right, which under RTL is the start. F2 Back chevron does not mirror
.hdr .back — only when it is an SVG		 "Back" means against the reading direction; in RTL that is rightward. An SVG path has no direction sense, so it keeps pointing left — i.e. forward. This is the one genuinely direction-dependent visual in the device, and it inverts the rule's stated exception: it does not need a physical utility to stay put, it needs an explicit flip to move.

⚠ The trap, found by measuring. This prototype originally drew the chevron as the character ‹ (U+2039) — which is in Unicode's Bidi_Mirrored set and flips for free under RTL. With a text glyph the fault is invisible and the obvious fix double-mirrors it back to wrong. The device now draws lucide's actual ChevronLeft path so it demonstrates what the app really does. F3 Space-separated numeric runs reorder
phones, date-times, ranges, the totals footer		 The largest fault, and invisible to the logical-tailwind grep — it is not CSS at all, it is Unicode bidi. Measured, not predicted (§3): +966 55 018 7712 renders as 7712 018 55 +966 — the failure mode the ticket named, to the character. font-variant-numeric:tabular-nums does nothing here — it sets glyph advance width, not character order. Isolate the whole value: direction:ltr; unicode-bidi:isolate, i.e. <bdi dir="ltr">. §3 measures exactly which values need it — it is a much shorter list than it first appears.
F4 Selected-row accent bar stays left
tr.sel{box-shadow:inset 3px 0 0}		 box-shadow offsets are physical and have no logical form. The bar sits against the left edge while the row now reads from the right, so it marks the trailing edge. 073's §7 mapping table calls this treatment logical and says it "mirrors in RTL for free" — that claim is wrong; it describes inset-inline-start, but the prototype implements box-shadow. The pseudo-element form 074 already specified: ::after with inset-inline-start:0 + inset-block:0. 074's grid CSS escape was already correct — only 073's HTML twin and its prose need fixing.
F5 Grid-frame notch stays top-left
.gridwrap{border-radius:0 9px 9px 9px}		 The square corner exists to meet the active tab. The tab strip mirrors, so the tab moves to the top-right — and the notch does not follow, leaving a rounded corner under the tab and a square corner in open air. border-radius:9px; border-start-start-radius:0. Identical output under LTR, correct under RTL.
F6 enableRtl is set on 1 grid of 7
BonusBuyInquiryPage.tsx:206		 Three problems in one line. It is a per-call-site prop set on exactly one of seven AgGridReact mounts; it reads document.documentElement.dir, which nothing in the app ever sets, so it is permanently false; and it is read during render with no subscription, so a later direction switch would not re-render the grid. See §5. One derived value beside the theme, spread into every grid. §5 gives the shape.
F7 Decorative arrows: no ruling
↗ track/view, ↻ refresh, ▾		 Not a bug — an unmade decision that will otherwise be made accidentally by whoever types the icon. Each needs an explicit mirror/no-mirror ruling, because CSS will not decide for them. §4 rules each one. Only ↗ is a real judgement call.
F8 No direction wiring exists
<html dir> is never set		 The app is en-only and core/i18n.ts comments that Arabic will be "a locale folder + dir="rtl"". But nothing sets dir today, so there is no switch to test against and F6's probe is dead code. This prototype had to force dir by hand. Out of scope to build the switch (Q3, §7) — but the spec should name the single place it will live, so F6's derived value has something to read.
Five of the eight are one-line CSS fixes that are byte-identical under LTR. F1, F4 and F5 can land in 073's build ticket with no RTL switch in existence and no visual change to the shipping LTR screen — they are simply the correct spelling of rules already written. F2, F3 and F7 need rulings; F6 and F8 are wiring.

3 · F3 in detail — the bidi fault

The ticket asked whether tabular-nums plus the browser's bidi algorithm is enough. It is not, and the two are unrelated. Below, every value is rendered inside an RTL paragraph: left column untreated, right column isolated. This is live text, not a screenshot.

These verdicts are measured, not reasoned. Every value below was rendered headless inside an RTL paragraph next to an Arabic label — the real case — and its visual token order read back off the client rects and compared to source. The result overturned two guesses in this prototype's own first draft, so trust the table over the intuition.

The rule, measured. A value breaks when it contains a space and begins or ends with a digit. Nothing else does. Specifically: bidi rule N1 resolves a neutral sitting between two same-direction strong characters to that direction — but it treats digits as right-directional for that test, so a space beside a digit takes the paragraph's RTL direction and cuts the run there. A hyphen, comma, decimal point or plus sign does not — which is why ERX-77120934, 1180-4471 and -9.20 all survive untouched. The space is the culprit, not the punctuation.

This makes the fix much smaller than feared. Ids, money, tracking codes and loyalty numbers — the bulk of the screen's figures — need nothing. The list is: phones (×3), Placed, Scheduled, and the grid's totals footer. Six fields, not the dozen the first draft assumed.
Wrap the whole value, never a fragment of a run. Measured the hard way: isolating just SMSA-91180442 inside ↗ Track SMSA-91180442 created a fault — it split an all-Latin run in two and the RTL paragraph then ordered the halves right-to-left, putting the id before its verb. Isolation is safe on a complete value and dangerous on a piece of one. (In the shipped screen the label will be Arabic, so the value is a genuine LTR island and the question does not arise — but the rule is worth stating, because it is the mistake a developer makes when they see the fault and reach for the nearest span.)

Over-application is otherwise free: isolating a value that was already correct never breaks it. So the reviewable rule can stay dumb — "server value mixing digits and spaces ⇒ wrap it" — rather than asking anyone to run N1 in their head.
The totals footer lands on 074, not here. 4 lines · 7 units is a pinnedBottomRowData cell, which 074 already specified via the pinnedRow* params. It is the one bidi fault that is inside the grid rather than in our own markup, so it needs the cellClass form of the fix, not the <bdi> component. Flagged back to 074's mapping as a follow-up.
Recommended mechanism: <bdi dir="ltr">, not a CSS class. <bdi> is unicode-bidi:isolate by construction, so the isolation survives a stylesheet that fails to load, and dir="ltr" forces the internal order rather than guessing it from first-strong. Proposed shape — one component in the shared layer, since every feature's ids and phones need it:

src/core/ui/Ltr.tsx → <bdi dir="ltr" className="tabular-nums">{children}</bdi>

It renders a value, never a label, so it is outside zero-literal i18n's remit — the text inside it is server data passed through as data. Six call sites on this screen (§3).

Inside AG Grid the same treatment arrives as a cellClass carrying direction:ltr; unicode-bidi:isolate — a cell is already its own element, so no wrapper is needed. Per §3 the only grid cell that needs it is the pinned totals row; the id, money and quantity columns are all measured safe.

(low confidence)		 The only genuine judgement call. It reads as "leaves the page, outward" — outward is away from the text's start edge, which mirrors. Guidance across design systems is split on this one, so it is flagged rather than asserted; see Q4 in §7. Cheap either way, and cheap to reverse.
Glyph or SVG decides whether you must act at all. Unicode's Bidi_Mirrored property makes a small set of characters flip themselves under RTL — ‹ › ( ) [ ] < > and friends. Everything else does not: ↗, ↻, ← and every SVG path render identically in both directions. Verified here by rendering ‹, ← and an SVG chevron side by side in an RTL run: the first flipped, the other two did not.

So the rule for reviewers is: if an icon should mirror, ship it as an SVG and flip it explicitly. Never rely on a punctuation character to be an icon — it either flips when you did not ask, or gets flipped twice when you did.
This is the "genuinely direction-dependent visual" the rule asks to be commented. logical-tailwind's exception clause covers a visual that must not mirror; the back chevron is the mirror image of that problem — it must mirror and CSS will not do it. Either way the rule's requirement is the same: a comment saying why. Proposed comment for the one flip: /* reading-order icon: "back" points against the text direction, so it mirrors */

5 · F6 — how enableRtl should be set

The ticket asked: per-grid prop, or theme-level? Neither, exactly. AG Grid v36 exposes enableRtl as a grid option, not a theme param — a theme cannot carry it, so "theme-level" is not available. But seven hand-written props is the shape that produced today's one-of-seven drift. The answer is one derived value, exported beside the theme, spread into every grid.

Today, verbatim: enableRtl={document.documentElement.dir === 'rtl'} — BonusBuyInquiryPage.tsx:206, the only occurrence in the repo. The other six grids (DeliveriesPage, DetailGrid, ChangeStoreDialog ×2, SimBonusBuyPanel, and the reworked Items grid) do not set it at all.

Proposed: a single useGridDirection() (or a plain exported constant, if Q3 rules the direction static) living next to omsGridTheme in src/core/theme/ag-grid-theme.ts, read from the same source of truth that sets <html dir> — not from document.documentElement, which is a DOM read with no subscription. Every AgGridReact then carries the same one prop, and the BBY call site's bespoke probe is deleted.

Everything inside the grid then mirrors itself — 074 already confirmed this by reading the v36 stylesheet: AG guards its own directional rules with .ag-ltr / .ag-rtl, so column order, pinned sides, header sort arrows and scroll direction flip without a class from us. That is exactly the boundary logical-tailwind draws around third-party widget internals, now verified. The single piece of hand-written grid CSS — 074's .ag-row-selected::after{inset-inline-start:0} — is logical by construction and mirrors correctly, as device C demonstrates in its HTML-table form. F4 is a fault in 073's prototype and prose, not in 074's specification.

6 · What this does not settle

Copy, deliberately. No Arabic string is in this prototype and none should be — the map rules translation content out of scope. What that leaves genuinely unknown is text metrics: Arabic at the same point size is taller and often wider than Latin, which will pressure the 340 px rail, the 10.5 px uppercase card headings (uppercase is meaningless in Arabic — it will simply not apply), and the white-space:nowrap on table headers. That is a copy-era problem, not a layout-mirroring one, and it belongs to whatever effort ships Arabic.

Not tested: the collapsed <900 px layout under RTL beyond F1 (the rail unstack is auto-fit, direction-neutral), and keyboard/focus order (DOM order is unchanged by dir, so it follows the visual mirror for free).
An artifact worth naming, because it looks like a bug and is not one. Look at the rail in devices B and C: Approval no. renders as .Approval no, Item no. as .Item no, Disc. as .Disc. A trailing full stop is a neutral at the end of a Latin run, so in an RTL paragraph it takes the paragraph's direction and jumps to the visual start.

This is not a layout fault and needs no fix — it is the Latin-copy method showing its edge. In the shipped screen those labels come from t() and will be Arabic, i.e. RTL runs whose trailing punctuation sits correctly with no help. It is recorded here only so the next reader does not open a ticket for it. It does mean one thing for the copy effort: if any label is ever left in Latin under an Arabic locale — a product name, a code, an untranslated string — it will show this, and the answer there is the same <bdi> treatment §3 specifies for values.

7 · The four rulings — all taken

Owner ruled all four this session, each as recommended. They are premises now, not questions; the reasoning is kept below because the spec will need it.

Q1 · The identity band's split. → RULED: let it mirror. Big line + sub-ids start-side, customer block end-side — mirrored, the customer lands on the left. The band is a two-column "what is this / whose is it" split, and both halves are read start-first in their own direction. Anchoring the customer to the physical right in RTL would freeze one half of a mirrored band against the flip and buy nothing — the block is end-aligned relative to its own text, which is what text-align:end already gives.
Q2 · The action bar, and cluster order. → RULED: both mirror. The terminal red pair lands bottom-left. 072's grammar is escape-start · clusters · terminal-end — it is stated in logical terms, so "commit-right" was always shorthand for "commit-end". Freezing the terminal pair on the right would put it on the same side as the mirrored pill rail's start and break the one spatial promise the bar makes.

And yes, clusters reverse too — that is what flex gives for free, and it is first-by-reading-order, not Fulfilment-always-leftmost. An operator scanning from the start edge meets Fulfilment first in both directions, which is the invariant worth keeping; "leftmost" is not.
Q3 · How much of this lands now? → RULED: (b) fixes + bidi. The dir switch and F6's derived value are not built now; F6/F8 stay recorded so the spec names where they will live. The three options as weighed:
· (a) Fixes only — F1/F4/F5 spelled correctly in the 073 build, F2/F3/F7 rulings recorded in the spec, no dir switch, no <bdi> component. Nearly free; leaves F3 as a documented debt.
· (b) Fixes + bidi (recommended) — also ship core/ui/Ltr.tsx and use it on the six fields §3 measured. Costs one small component and six wrappers, and it is invisible under LTR, so it can never regress the shipping screen. The reason to do it now: these wrappers must go on the exact fields 073/079/081 are defining this month — doing it later means re-reading every one of them.
· (c) All of it — plus the dir switch and F6's derived value. Buys a testable RTL mode, but builds a switch with no locale behind it.
Q4 · Does ↗ mirror? → RULED: yes, to ↖. Consistent with the back chevron's "direction is relative to reading order" logic. Design-system guidance genuinely splits here, so this is the one ruling on the page held with low confidence — and it is a two-character change, trivially reversible if it reads wrong once Arabic copy is in.

Note it is not a free flip. Per §4, ↗ (U+2197) is not in Unicode's Bidi_Mirrored set, so this ruling costs an explicit rtl:-scale-x-100 on the icon — the same treatment as the back chevron, and subject to the same "SVG, not a glyph" rule.
